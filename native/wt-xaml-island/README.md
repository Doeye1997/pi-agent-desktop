# Pi session display host

`pi-session-display-host.exe` is the Windows-only WinUI/XAML Island adapter used by the Electron cockpit.

The Electron main process starts it from `PI_DESKTOP_WINDOWS_TERMINAL_HOST`, packaged resources, or this directory. It must not resolve or launch `wt.exe`.

## Transport

stdin/stdout are newline-delimited JSON. The host owns `TermControl`, the ConPTY, and bundled Pi process. Electron never receives terminal bytes.

Commands:

- `mount`: `{ request: { session, size, parentWindowHandle } }`
- `focus`: `{ sessionId }`
- `write`: `{ sessionId, data }`
- `resize`: `{ sessionId, size: { cols, rows } }`
- `bounds`: `{ sessionId, bounds: { x, y, width, height, scaleFactor } }`
- `theme`: `{ theme: "light" | "dark" }`
- `dock`: `{ sessionId, state: { cwdLabel, worktreeLabel, usageLabel, modelLabel, thinkingLabel, mcpLabel, cwdChoices, worktreeChoices, modelChoices, thinkingChoices, skillChoices } }`
- `hide`: `{ sessionId }` (keeps the background session alive)
- `dead`: `{ sessionId }`
- `kill`: `{ sessionId }`
- `dispose`

Events:

- `{ type: "mark", sessionId, mark: "running" | "dead" }`
- `{ type: "action", sessionId, action: "relocate" | "browse-cwd" | "model" | "thinking", value? }`
- `{ type: "error", sessionId?, code, message }`
- `{ type: "host-error", code, message }`

The host must fail loudly when the XAML Island or `TermControl` cannot be created. No xterm, WezTerm, external Windows Terminal window, or silent fallback is valid.

## Local build

The host links only against the Windows SDK. It dynamically loads the already-built
Windows Terminal WinRT components from the same directory as the executable.

```powershell
msbuild native\wt-xaml-island\pi-session-display-host.vcxproj /t:Build /p:Configuration=Release /p:Platform=x64 /p:TerminalRoot=F:\Toolchain\windows-terminal-src
```

Before launching, place these runtime files in a `runtime` directory beside
`pi-session-display-host.exe`, or directly beside the executable:

- `Microsoft.UI.Xaml.dll` from the Microsoft.UI.Xaml 2.8 x64 appx
- `resources.pri` generated by Windows Terminal's `_WTPrepareUnpackagedLayoutForRun` target (its resource-map name must be `Application`; the PRI copied directly from the Microsoft.UI.Xaml appx is not sufficient)
- `Microsoft.Toolkit.Win32.UI.XamlHost.dll` from Microsoft.Toolkit.Win32.UI.XamlApplication 6.1.3
- `Microsoft.Terminal.Control.dll`, `TermControl.xbf`, and `SearchBoxControl.xbf`
- `TerminalConnection.dll` and `Microsoft.Terminal.UI.dll`

`PI_DESKTOP_WINDOWS_TERMINAL_RUNTIME` can point to a separate runtime directory during development.

When staging from a custom build, `PI_WINDOWS_TERMINAL_PRI_PATH` can point directly
to the merged unpackaged `resources.pri`. Otherwise the preparation script expects
it at `bin/x64/{Release,Debug}/WindowsTerminal/resources.pri` below
`PI_WINDOWS_TERMINAL_ROOT`.

`npm run dev` reuses a complete `build/toolchains/windows-terminal/win-x64`
staging directory automatically. If it is missing, set the staging source
variables below before starting Vite.

`npm run pack` / `npm run dist` stages this directory from
`PI_WINDOWS_TERMINAL_RUNTIME_SOURCE` or `PI_WINDOWS_TERMINAL_ROOT` plus
`PI_WINDOWS_TERMINAL_UIXAML_ROOT` and the x64 MSVC CRT directory from
`PI_WINDOWS_TERMINAL_CRT_ROOT` or `VCToolsRedistDir`. Set
`PI_WINDOWS_TERMINAL_XAML_APPLICATION_ROOT` when the XamlApplication package is
not extracted under `build/toolchains/Microsoft.Toolkit.Win32.UI.XamlApplication.6.1.3`.
Set `PI_WINDOWS_TERMINAL_APP_CRT_ROOT` when the x64 App CRT files cannot be
resolved from the local Windows component store.
